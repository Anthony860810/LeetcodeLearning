# 567. Permutation in String

## 題目描述

給定兩個字串 `s1` 和 `s2`，判斷 `s2` 是否包含 `s1` 的任意排列組合。

例如 `s1 = "ab"`、`s2 = "eidbaooo"`，因為 `s2` 包含 `"ba"`，所以答案是 `true`。

## Solution 1

使用 `unordered_map` 記錄 `s1` 的字元數量，再從 `s2` 的每個位置嘗試檢查長度為 `s1.size()` 的區間。每次都複製一份 map，因此重複工作較多。

## Solution 2

使用長度固定為 26 的 `vector<int>` 記錄字元頻率，並用固定大小的 sliding window 掃描 `s2`。

## Solution 3：`std::array` 固定視窗

你的優化版本將頻率表改成：

```cpp
array<int, 26> target = {};
array<int, 26> window = {};
```

每個視窗的大小固定為 `s1.size()`。視窗向右移動時，只需要加入新字元並移除最左邊的字元：

```cpp
++window[s2[idx] - 'a'];
--window[s2[idx - s1.size()] - 'a'];
```

`std::array` 的大小在編譯期固定，資料連續配置，不需要動態配置；相較於 `vector<int>`，這通常具有較低的常數成本，也更能表達「固定 26 個英文字母」的意圖。

不過 `target == window` 仍會逐一比較 26 個元素。因為 26 是固定常數，所以複雜度仍然是 `O(N)`，但在每次移動視窗時會多做最多 26 次比較。

## Solution 4：維護匹配數量

進一步的優化是不再每次比較完整的 26 格陣列，而是維護 `matched`：目前 26 個字母中，有幾個字母的頻率與目標頻率相同。`target` 已經先記錄 `s1` 的頻率，而 `window` 一開始全部是 0，因此初始化時只把 `target` 頻率也是 0 的字母算進 `matched`。

當某個位置更新前後，依序判斷它是否從「相等」變成「不相等」，或從「不相等」變成「相等」，就能同步更新 `matched`。當 `matched == 26` 時，代表整個視窗的字元頻率完全相同。

這樣每次滑動視窗只需處理加入與移除的兩個字元，不需掃描整個陣列。實際上因為字元種類固定為 26，Solution 3 與 Solution 4 的 Big-O 都是 `O(N)`；Solution 4 主要減少的是常數成本，當字元種類變大時差異會更明顯。

## 複雜度

| 方法 | 時間複雜度 | 額外空間複雜度 |
| --- | --- | --- |
| Solution 1 | 最差 `O(N * M)` | `O(字元種類)` |
| Solution 2 | `O(N)` | `O(字元種類)` |
| Solution 3 | `O(N * 26)`，等同 `O(N)` | `O(26)`，等同 `O(1)` |
| Solution 4 | `O(N)` | `O(26)`，等同 `O(1)` |

其中 `N = s2.size()`，`M = s1.size()`。若題目保證只有小寫英文字母，`26` 是固定常數。
